# 实现结构

## 模块

| 文件 | 职责 |
|---|---|
| xreal_windows.py | 定向摄像头采集、遥测解析、重排解码、双目配对、清理与交互主循环 |
| viewer_display.py | Windows 屏幕枚举、按比例留边、设置读写 |
| video_recorder.py | 处理后画面 MP4 录制、时间轴补帧、音频合成调度 |
| audio_capture.py | 麦克风选择、后台 WAV 写入、音视频时间起点补偿和 AAC 合成 |
| raw_capture.py | 原始字节与软件时间表的保存、读取及一致性校验 |
| export_recording.py | 从原始录制离线生成单路或双目视频 |
| check_stereo.py | 物理左右镜头遮挡确认与分眼测试图 |
| tests/ | 无硬件依赖的回归测试与合成数据 |

主程序与模块位于仓库根目录，保持双击启动器及直接导入方式，不引入额外打包框架。

## 数据流

```text
UVC Camera 0 → FFmpeg DirectShow 原始字节复制 → 有限队列
    → [可选原始保存] → 遥测校验/镜头分组 → 重排与方向纠正
    → 各镜头独立清理 → 按编号配对或单路筛选 → 镜像/旋转/交换
    → [可选 MP4 保存] → 显示留边与操作提示 → OpenCV 窗口

选定麦克风 → PortAudio 回调 → 写入队列 → WAV
    → 录制停止 → 时间起点补偿 → AAC 音轨 + 原视频 → 新 MP4
```

## 当前设备的原生布局

FFmpeg 在 Windows 上提供 YUY2、640×241、约 60 fps；直接复制后每帧 308,480 字节，可解释为 640×482 的 8 位数据。前 480 行为图像，第 480 行为元数据。以下字段根据当前设备实测，不是官方协议保证：

- 元数据字节 59：分组 0/1。
- 字节 18–21：小端配对编号，两组共享；不依据奇偶帧或固定到达顺序判定左右。
- 字节 51–56：实测尺寸标记，用于识别当前布局。
- 字节 26–27 可随启动变化，不能当作固定标记；末行在部分帧也会变化。

上游 macOS 遥测布局另保留独立解析路径。128×2400 字节重排及黑边相位检测沿用上游算法思路。两路方向相差 180°，再通过用户设置做显示修正。

配对缓存最多 8 个编号，不用旧帧冒充缺失镜头。清理使用各自的列条纹估计；原生模式禁用逐帧直方图均衡，减少亮度跳动。

## 文件与时间

- 原始目录：frames.bin、frames.csv、capture.json。只保存交给主循环的数据；不是直接 USB 总线无损抓包。
- 处理后录像：MP4、CSV；录音启用时另有 WAV 和 with_audio.mp4。
- CSV 与画面时间为软件时间。麦克风使用 ADC 回调时间估计首采样时刻，与首视频处理时刻补偿；没有硬件同步。
- 设置与录制均为本地文件，Git 忽略相应产物。
