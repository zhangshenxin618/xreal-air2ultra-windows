# 验证记录与待验证项

## 已有实际设备证据

- Windows 识别 Air 2 Ultra 为 UVC Camera 0，标准 USB 视频驱动已启动。
- 实际媒体格式为 640×241、YUY2、约 60 fps，能够复制原始字节并还原可辨识场景。
- 开发过程中完成连续 300 帧解码、150 对双目配对，输出 960×640。
- 用户反馈单路、双目预览、普通 2D 全屏及按键操作可用。
- 用户完成实际双侧遮挡，确认该设备分组 0 为佩戴时左镜头、分组 1 为右镜头。此本机设置不随公共仓库发布。

## 自动测试覆盖

- 异常帧跳过和后续恢复，模拟摄像头释放。
- 不同到达顺序、缺帧、缓存上限。
- 分路旋转与镜像、交换位置、普通与 SBS 留边。
- 设置保存和异常设置恢复。
- 双侧遮挡识别及不明确样本拒绝，不修改原设置。
- 合成原始帧逐字节保存/读回；损坏文件拒绝；单路与双目导出后解码。
- MP4 录制、软件时间轴、缺帧时长。
- 模拟麦克风回调写 WAV、AAC 音轨编解码、早/晚起点补偿和麦克风不可用回退。
- 预览窗口与终端按键输入。

公共测试使用合成场景，不能替代实际硬件、真实声音和佩戴观察。

## 仍待验证

- 眼镜麦克风虽可枚举，但开发工具环境无法实际打开。没有声称已录到真实声音。用户应试录说话和拍手，检查是否有声及音画偏移。
- 3D/SBS 眼镜分眼显示未完成佩戴验证；LEFT/RIGHT 测试图只是验证入口。
- 实际镜头标定、畸变校正、深度精度、视野/瞳距匹配未开展。
- 不同固件、电脑和 USB 接口未做兼容矩阵。
- 长时间录制的丢帧率、音频漂移、热稳定性未做定量测量。

发布的代码不包含实拍录像、麦克风录音或本地日志。GitHub Actions 的云端状态应以实际执行结果为准，不以本地通过替代。
